# Update Spec

## 1. 版本目标

本轮版本目标是将前端聊天工作台升级为支持本地历史会话的在线 Demo，并修复 AI 回复中 Markdown 加粗语法未渲染的问题。

本轮更新面向面试官快速体验：面试官打开在线 URL 即可试用，不需要下载项目、不需要配置 `.env`、不需要本地启动前后端服务。历史对话默认保存在面试官自己的浏览器本地，并提供历史导入/导出能力，方便备份和迁移。

## 2. 功能范围

- 重构侧边栏为会话管理：
  - 保留品牌区和收起侧边栏能力。
  - 提供醒目的 `开启新对话` 操作。
  - 展示历史会话列表。
  - 移除 `保单分析`、`理赔辅助`、`最近查询`。
- 新增前端本地会话历史：
  - 会话包含 `id`、`title`、`messages`、`createdAt`、`updatedAt`。
  - 默认标题取第一条用户消息；没有用户消息的空会话显示为 `新对话`。
  - 会话变更后保存到浏览器本地存储。
  - 页面刷新后恢复历史会话和当前会话。
- 支持历史会话查看和继续提问：
  - 点击历史会话后，主聊天区展示该会话完整上下文。
  - 当前会话在侧边栏有明确选中态。
  - 在历史会话中继续提问时，消息追加到当前选中会话。
- 支持历史导入/导出：
  - 用户可以将历史会话导出为 JSON 文件。
  - 用户可以从 JSON 文件导入历史会话。
  - 导入失败时给出明确错误提示，不覆盖当前有效历史。
- 修复 AI 回复重点文本显示：
  - AI 消息支持解析 `**bold**`。
  - 加粗内容渲染为真正的粗体样式。
  - 用户消息继续按纯文本显示，不执行 Markdown 渲染。
- 支持在线 Demo 交付：
  - 前端可以部署为公网可访问页面。
  - 后端服务部署在服务端环境。
  - API Key、Token、数据库凭据、ES、DashScope、Tavily 配置只放在服务端安全配置中。

## 3. 不做什么

- 不让面试官下载项目源码或手动配置 `.env` 才能体验。
- 不把 API Key、Token、密码、私钥或数据库凭据下发到前端。
- 不新增用户账号、登录、权限或管理后台。
- 不做云端历史同步。
- 不新增后端会话 API。
- 不新增数据库或修改数据库 Schema。
- 不修改 ES、DashScope、Tavily、RAG 检索逻辑。
- 不修改 `/api/chat` 和 `/api/health` 的接口契约。
- 不恢复或扩展 `保单分析`、`理赔辅助` 的独立业务能力。
- 不移动 `backend/docs` 运行时知识库目录。

## 4. 影响范围

- 前端主应用状态管理：从单一 `messages` state 调整为当前会话 + 会话列表。
- 侧边栏组件：从静态导航调整为会话管理和历史列表。
- 消息渲染组件：AI 消息增加基础 Markdown 加粗渲染。
- 浏览器本地存储：新增会话历史保存、读取、容错逻辑。
- 历史文件能力：新增 JSON 导出和导入交互。
- 部署配置：上线环境需要保证前端页面可访问，且 `/api/chat`、`/api/health` 能正确到达后端服务。
- 不影响后端检索服务、运行时资料库和现有 API 契约。

## 5. 兼容要求

- 保持现有 `SearchMode`：`quick`、`semantic`、`web`。
- 保持发送请求格式：`POST /api/chat` with `{ message, mode }`。
- 保持后端流式 `text/plain` 响应读取方式。
- 保持 `GET /api/health` 健康检查能力。
- 本地开发环境继续支持 Vite `/api` proxy 到 `http://127.0.0.1:7870`。
- 生产环境不能依赖面试官本机的 `localhost` 后端。
- 没有历史数据时，页面应正常进入一个默认新会话。
- 本地历史数据异常或解析失败时，应自动降级为默认新会话，不阻塞页面加载。
- 导入的历史 JSON 结构不合法时，不应破坏当前历史。

## 6. 实现约束

- 优先在前端内实现本轮会话历史能力，不引入后端改动。
- 历史会话只保存消息文本、角色、模式、来源和时间等非敏感 UI 数据。
- 不保存 API Key、后端配置、检索原始上下文、环境变量或服务端凭据。
- Markdown 渲染需控制范围，至少支持 `**bold**`；如引入第三方库，不允许开启危险 HTML 渲染。
- 流式回答时，AI 消息必须写回发起请求时所属的会话，避免切换会话后串写。
- 导入历史时需要校验数据结构，避免异常 JSON 造成页面崩溃。
- 侧边栏收起状态下仍应保留 `开启新对话` 和历史会话的可识别入口或 tooltip。
- UI 风格继续匹配现有 Corporate / Modern / Minimal 设计语言。
- 上线部署时，敏感配置只能通过服务端环境变量或平台 Secret 管理。

## 7. 验收标准

- 面试官打开在线 URL 后，不需要下载配置即可进入问答页面。
- 侧边栏只展示会话管理相关内容，不再展示 `保单分析`、`理赔辅助`、`最近查询`。
- `开启新对话` 可创建新的空会话。
- 完成至少一轮问答后，历史列表中出现对应会话。
- 历史会话标题可读，默认来自第一条用户问题。
- 点击历史会话可查看该会话完整上下文。
- 刷新页面后，历史会话仍存在。
- 可以导出历史会话 JSON 文件。
- 可以导入合法历史会话 JSON 文件并展示到历史列表。
- 导入非法 JSON 或非法结构时，页面不崩溃，当前历史不丢失。
- AI 回复中的 `**重点内容**` 渲染为粗体。
- 正常 bold 文本两侧不显示原始 `**`。
- 用户消息不执行 Markdown 渲染。
- 前端 `npm run lint` 和 `npm run build` 通过。

## 8. 回归测试点

- 新会话首屏欢迎语显示正常。
- 建议问题仍可点击并发起问答。
- 三种检索模式仍可切换并发送。
- `/api/chat` 请求仍能正常流式返回。
- `/api/health` 可正常访问。
- 后端异常或未启动时，前端仍显示错误信息。
- 流式回答中页面滚动到底部行为正常。
- 切换历史会话后再提问，消息追加到当前选中会话。
- 流式回答期间切换会话，不会把回答写入错误会话。
- 页面刷新后，当前会话与历史列表恢复合理。
- 收起/展开侧边栏行为正常。
- 生产环境不向浏览器暴露服务端密钥。

## 9. 风险

- 如果会话状态更新与流式响应绑定不严谨，可能出现 AI 回复写入错误会话。
- 如果本地存储数据结构未做容错，损坏数据可能导致页面加载失败。
- 如果 Markdown 渲染配置不当，可能带来 HTML 注入风险。
- 如果历史导入没有校验，可能覆盖或破坏当前有效历史。
- 如果生产环境 API 地址或反向代理配置不正确，面试官能打开页面但无法发起问答。
- 如果后端仍依赖本机 `backend/.env` 且未迁移到服务器 Secret，在线 Demo 会不可用。
- 如果移除 `最近查询` 后没有保留建议问题入口，首屏快捷提问体验可能变弱。
